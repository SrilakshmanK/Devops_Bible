# Chapter 01 — What Is Artificial Intelligence?

Start with the broadest concept.

---

## 1.1 What Does "Intelligence" Mean?

Before defining AI, think about what humans do that appears intelligent:

* recognize patterns
* learn from experience
* predict
* reason
* classify
* plan
* communicate
* make decisions
* solve problems

AI attempts to reproduce some of these capabilities computationally.

---

## 1.2 AI vs Machine Learning vs Deep Learning

Understand the hierarchy:

```text
Artificial Intelligence
│
├── Rule-Based Systems
│
├── Machine Learning
│   │
│   ├── Classical ML
│   │
│   └── Deep Learning
│       │
│       └── Neural Networks
│
└── Generative AI
    │
    ├── LLMs
    ├── Image Models
    ├── Audio Models
    └── Multimodal Models
```

Important:

> AI is the broad field.

> Machine Learning is one way to build AI systems.

> Deep Learning is a family of machine-learning approaches based primarily on neural networks.

> LLMs are deep-learning models specialized in language and related modalities.

---

## 1.3 Rule-Based AI

Example:

```python
if temperature > 38:
    diagnosis = "fever"
```

The programmer explicitly defines the rule.

---

## 1.4 Machine Learning

Instead of explicitly writing every rule:

```text

 ↓

 ↓

 ↓

```

The model learns patterns from examples.

---

## 1.5 Generative AI

Traditional ML often predicts:

```text

```

Generative models can produce:

```text

code
```

Understand this distinction carefully.

# Chapter 02 — Machine Learning From First Principles

You need enough ML fundamentals to understand what happens inside modern AI systems.

---

## 2.1 The Basic ML Problem

Suppose we want:

```text
Input → Prediction
```

For example:

```text
House features → House price
```

A model attempts to learn:

```text
f(x) ≈ y
```

where:

```text
x = input
y = target
```

---

## 2.2 Parameters

Understand the idea of model parameters.

A simple linear model:

```text
y = wx + b
```

where:

```text
w = weight
b = bias
```

Training means finding parameter values that produce useful predictions.

---

## 2.3 Loss

A model needs a way to measure how wrong it is.

```text
Prediction
     ↓
Compare with target
     ↓
Loss
```

Lower loss generally means the model is fitting the training objective better.

---

## 2.4 Optimization

Understand the basic idea of:

```text
Initialize parameters
 ↓
Make prediction
 ↓
Calculate loss
 ↓
Calculate gradients
 ↓
Update parameters
 ↓
Repeat
```

This is the foundation of gradient-based learning.

---

## 2.5 Gradient Descent

You do not need to become a calculus expert.

But understand:

> The gradient tells us the direction in which the loss changes.

Gradient descent updates parameters toward lower loss.

---

Your goal is understanding, not performance.

# Chapter 07 — From Neural Networks to Language Models

Now move toward language.

---

## 7.1 Why Language Is Difficult

Language contains:

* ambiguity
* context
* syntax
* semantics
* long-range relationships
* multiple meanings

Example:

> "I went to the bank."

What does "bank" mean?

The surrounding context matters.

---

## 7.2 Language Modeling

A language model estimates:

```text
P(next token | previous tokens)
```

For example:

```text
The sky is
        ↓
blue
```

The model predicts likely continuations.

---

## 7.3 Autoregressive Generation

A simplified process:

```text
Prompt
 ↓
Predict next token
 ↓
Append token
 ↓
Predict next token
 ↓
Append token
 ↓
...
```

---

## 7.4 Why This Can Produce Complex Behavior

A model trained on enormous quantities of language learns statistical patterns involving:

* syntax
* facts
* concepts
* style
* code structures
* relationships

This does not mean the model stores a perfect database of facts.

That distinction becomes critical later.

---

# Chapter 08 — Tokens & Tokenization

This is one of the most important LLM concepts.

---

## 8.1 What Is a Token?

A token is a unit of text processed by a language model.

It might correspond to:

* a word
* part of a word
* punctuation
* whitespace-related fragments

---

## 8.2 Why Not Process Whole Words?

Vocabulary size would become difficult to manage.

Subword tokenization provides a compromise.

---

## 8.3 Tokenization

Conceptually:

```text
"Understanding AI systems"
          ↓
["Understanding", " AI", " systems"]
```

Actual token boundaries depend on the tokenizer.

---

## 8.4 Token IDs

Models ultimately operate on numeric representations.

```text
text
 ↓
tokens
 ↓
token IDs
 ↓
embeddings
 ↓
model
```

---

## 8.5 Input and Output Tokens

An API request can involve:

```text
input tokens
+
output tokens
=
total token usage
```

This becomes important for:

* cost
* latency
* context limits

---

# Chapter 09 — Embeddings & Semantic Representation

This chapter introduces the idea needed for V10.

---

## 9.1 What Is an Embedding?

An embedding represents an object as a vector.

Conceptually:

```text
"cat"
 ↓
[0.12, -0.42, 0.81, ...]
```

---

## 9.2 Semantic Space

Similar concepts can occupy nearby regions of the vector space.

Conceptually:

```text
cat
kitten
dog
automobile
database
```

are represented in a high-dimensional space.

---

## 9.3 Similarity

Study:

* cosine similarity
* dot product
* Euclidean distance

---

## 9.4 Why Embeddings Matter

Embeddings allow systems to perform:

* semantic search
* clustering
* recommendation
* classification
* retrieval

---

## 9.5 Important Distinction

An embedding is not:

> "the meaning of a sentence stored as a perfect vector."

It is a learned numerical representation useful for particular similarity and downstream tasks.

---

```text

```

# Chapter 11 — Attention Mechanism Deep Dive

Do not skip this chapter.

---

## 11.1 The Core Problem

For each token, the model needs to determine:

> Which other tokens are relevant to understanding this token?

---

## 11.2 Query, Key, Value

Understand:

```text
Query
Key
Value
```

and conceptually:

```text
Attention(Q,K,V)
```

---

## 11.3 Attention Scores

The model calculates how strongly tokens should attend to one another.

---

## 11.4 Self-Attention

Each token can interact with other tokens within the attention mechanism.

---

## 11.5 Multi-Head Attention

Instead of one attention relationship:

```text
Head 1
Head 2
Head 3
...
Head N
```

Different heads can learn different relationship patterns.

---

## 11.6 Causal Attention

For autoregressive language generation, a token should not attend to future tokens during training.

Conceptually:

```text
Token 1 → sees 1
Token 2 → sees 1,2
Token 3 → sees 1,2,3
```

---

# Chapter 14 — LLM Inference

Training and inference are different operations.

---

## 14.1 Training

```text
Data
 ↓
Compute gradients
 ↓
Update parameters
```

---

## 14.2 Inference

```text
Prompt
 ↓
Model
 ↓
Prediction
 ↓
Output
```

The model parameters are normally not updated during ordinary inference.

---

## 14.3 Generation

The model repeatedly predicts tokens.

```text
Input
 ↓
Token prediction
 ↓
Token
 ↓
Next prediction
 ↓
Token
 ↓
...
```

---

## 14.4 Temperature

Understand temperature as a control affecting the distribution from which tokens are selected.

Higher temperature generally allows more variation.

Lower temperature generally makes output more concentrated around high-probability choices.

---

## 14.5 Top-k

Restrict sampling to a limited set of likely next tokens.

---

## 14.6 Top-p

Sample from a dynamically selected probability mass.

---

## 14.7 Deterministic vs Stochastic Generation

Understand why repeated calls may or may not produce identical outputs depending on model and generation settings.

# Chapter 15 — Context Windows & Conversation State

## 15.1 Context Window

A model can only process a finite amount of context for a particular request.

Conceptually:

```text
┌─────────────────────────────┐
│       Context Window        │
│                             │
│ system instructions         │

│ user input                  │
│ retrieved documents         │
│ tool results                │
│ generated output            │
```

---

## 15.2 Context Is Not Memory

A model receiving previous messages does not mean it possesses unlimited permanent memory.

Understand the difference between:

* model parameters
* context
* application memory
* database
* retrieval

## 15.3 Context Budget

Every additional piece of context can affect:

* token usage
* latency
* cost
* available output space

## 15.4 Context Engineering

* what to exclude

# Chapter 20 — LLM Limitations, Hallucinations & Reliability

This is one of the most important chapters.

---

## 20.1 What Is a Hallucination?

A model can produce information that is:

* incorrect
* unsupported
* fabricated
* outdated

while sounding confident.

---

## 20.2 Why Does This Happen?

Language models optimize their training objective and generation behavior.

They are not inherently truth databases.

---

## 20.3 Knowledge vs Retrieval

A model's internal parameters are different from querying a current external source.

---

## 20.4 Common Failure Modes

Study:

* fabricated facts
* incorrect calculations
* outdated information
* instruction following failures
* prompt injection
* context confusion
* malformed structured output
* tool misuse

---

## 20.5 Reliability Techniques

Use:

```text
validation
retrieval
tool calls
structured outputs
evaluation
constraints
human review
```

where appropriate.

---

## 20.6 Confidence

Do not assume:

> confident wording = high confidence.

The model's linguistic certainty is not automatically a calibrated probability of correctness.

---

# 🔬 V09 Engineering Principles

Throughout the volume, avoid these mistakes.

## ❌ Mistake 1 — Treating LLMs as magic

Instead:

```text
Input
 ↓
Tokens
 ↓
Embeddings / representations
 ↓
Transformer computation
 ↓
Probability distribution
 ↓
Token selection
 ↓
Output
```

---

## ❌ Mistake 2 — Treating an LLM as a database

A model's learned parameters are not equivalent to a reliable, queryable database.

---

## ❌ Mistake 3 — Assuming fluent output is correct output

Language quality and factual correctness are different dimensions.

---

## ❌ Mistake 4 — Believing prompting solves everything

Some problems require:

* retrieval
* tools
* validation
* application logic
* databases
* deterministic code

---

## ❌ Mistake 5 — Building AI applications without evaluation

If you cannot measure whether the system improved, you are guessing.

---

## ❌ Mistake 6 — Giving the model unrestricted authority

Models should operate inside controlled application boundaries.
