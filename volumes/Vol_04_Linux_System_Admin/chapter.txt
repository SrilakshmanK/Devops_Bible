# 🐧 Volume 04 — Linux Fundamentals & System Administration

## 🎯 Volume Objective

Develop a deep, practical understanding of Linux as an operating system and become comfortable **operating, configuring, troubleshooting, securing, and maintaining Linux systems entirely from the command line**.

This volume is **Ubuntu-first** because Ubuntu is your current environment.

By the end of this volume, you should be able to take a fresh Ubuntu machine and turn it into a usable, remotely accessible, reasonably hardened server.

---

# 🧠 Why This Volume Exists

Almost everything you will encounter later in DevOps and AI infrastructure sits on top of Linux:

```text
Your Application
      ↓
Docker
      ↓
Kubernetes
      ↓
Cloud
      ↓
Virtual Machines
      ↓
Linux
      ↓
CPU / Memory / Storage / Network
```

Linux is therefore not just another tool to learn.

It is the **operating environment underneath much of modern infrastructure**.

You should eventually be able to look at a Linux server and understand:

```text
What is running?
        ↓
Who is running it?
        ↓
Where are its files?
        ↓
What permissions does it have?
        ↓
What resources is it consuming?
        ↓
What network ports does it use?
        ↓
What service manages it?
        ↓
What logs does it produce?
        ↓
What happens when it fails?
```

That mindset is more important than memorizing commands.

---

# 🧭 Learning Philosophy

Throughout this volume:

### 1. Understand before memorizing

Do not memorize:

```bash
chmod 755 file
```

without understanding:

```text
7 = owner permissions
5 = group permissions
5 = others permissions
```

---

### 2. Use the terminal as the primary interface

GUI tools are allowed for convenience.

But your practical work should primarily use:

```text
Terminal
    ↓
Shell
    ↓
Commands
    ↓
Kernel
    ↓
System
```

---

### 3. Learn the reason behind every command

For every important command ask:

```text
What does it do?
Why does it exist?
What part of Linux does it interact with?
What information does it show/change?
What could go wrong?
How can I verify the result?
```

---

### 4. Practice deliberately breaking things

A large part of Linux administration is troubleshooting.

You should intentionally create controlled failures such as:

```text
Wrong permissions
Wrong service configuration
Stopped service
Blocked port
Incorrect mount
Full disk
Broken DNS
Invalid configuration
```

Then diagnose them.
